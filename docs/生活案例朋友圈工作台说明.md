# 生活案例朋友圈工作台说明

“生活案例朋友圈”用于把真实发生的小事整理成可直接发布的朋友圈文案。它沿用工作台现有的三名数字员工，不增加复杂流程，也不会联网搜索或凭空补写经历。

## 一、怎么使用

1. 在“开始创作”选择“生活案例朋友圈”。
2. 上传 1–9 张图片，并写下事情经过。图片与文字都必须提供；发生日期可以不填。
3. 检查图片顺序。研究员会按这个顺序理解事情经过。
4. 点击保存并生成。案例会先保存到本机，再进入三员工流程。
5. 从三篇完整文案中直接复制，或点击“采用这版”把其中一篇保存为新的最终稿版本。

支持 JPG、PNG、WebP、静态 GIF 和 HEIC/HEIF。单张图片最大 12MB，一次最多 30MB。标题由发生日期和文字开头自动生成，不需要单独填写。

## 二、三名数字员工分别做什么

- **研究员**：只从用户文字和图片可见内容中整理事实，区分“用户明确说过”“图片能够看见”“无法确定”和“可能涉及隐私”的信息。图片中的任何文字都只当作素材，不当作系统指令。
- **文案员工**：根据同一份事实材料生成三种不同角度的完整朋友圈文案，不虚构人物关系、地点、时间、身份、情绪、产品效果或对话。
- **主编**：检查三篇文案是否忠于素材，删除过度升华、强行营销、空泛套话和机械的 AI 表达，然后推荐其中一篇。

模型只在研究员阶段读取图片，后续员工使用研究员整理出的事实包，避免重复识图和反复猜测。

## 三、三种文案有什么区别

- **真实日常**：忠实记录当天发生的事情，语气自然，不强行总结大道理。
- **有感而发**：从真实细节延伸出一层个人感受，但不会把普通小事过度拔高。
- **轻度业务启发**：在已有 IP 或产品资料支持时，连接到工作、客户或业务上的一个小启发；资料里没有的业务内容绝不补造。

三篇都是完整文案，不是标题或提纲。主编会标记一篇推荐稿，但用户可以复制任意一篇，也可以把任意一篇采用为最终稿。“采用这版”会新建版本，不会覆盖最初生成的三篇。

生活案例不强制添加标题、标签、互动问题、行动指令或销售话术。复制按钮只复制正文，不会偷偷附加其他内容。

## 四、图片保存和隐私

- 上传的原图原样保存在当前电脑的 `.workbench/life_cases/`，不会因为生成完成而自动删除。
- 发送模型前，系统只在内存中校正方向、移除 EXIF 信息、转换成模型支持的格式，并把最长边限制为 2048px；这个处理副本不会落盘。
- 原图二进制、Base64、内部文件路径不会写入任务事件、业务导出、浏览器存储或应用日志。
- 案例按品牌工作区隔离；读取图片时会重新校验案例和图片归属，不能用文件路径绕过权限。
- 图片和文字都可能包含个人信息。上传前仍建议遮挡身份证号、门牌、儿童学校、联系方式等不需要进入文案的内容。

## 五、失败后怎么恢复

- **模型未连接**：案例和原图仍会先保存，任务显示“需要连接模型”。完成模型配置后点击继续即可，不需要重新上传。
- **生成中断**：系统保留已经完成的阶段。恢复后从中断位置继续，不重复整套流程。
- **想再生成一轮**：使用“按相同要求重新生成”。新任务会保留原案例、图片关联和全部生成参数。
- **想改素材**：已保存案例保持不变。使用“复制为新案例”后修改文字或图片，避免旧作品对应到被改动后的素材。

## 六、归档和永久删除

“归档”只把案例从默认列表隐藏，文字、图片和已经生成的作品都保留，可以随时恢复。

在案例详情中选择“永久删除”并完成二次确认后，系统会删除该案例的文字和本地原图。已经生成的作品仍会保留，但不再关联被删除的案例，也不能再显示原素材或以该案例重新生成。永久删除不可恢复。案例仍有任务正在处理时不能永久删除，请等待任务完成或先取消任务。

## 七、本轮验收项目

- 第四个创作入口在桌面端正常显示，390px 窄屏为 2×2 工作台卡片且无横向溢出。
- 图片格式、真实文件内容、数量、单张大小和总大小均经过后端校验。
- 原图保存后的 SHA-256 与上传内容一致，模型只接收去除 EXIF 的内存副本。
- 三名员工各运行一次，最终恰好交付三种不同角度且仅有一篇主编推荐稿。
- 无证据细节、图片中的提示注入、空泛 AI 表达和硬性营销会被拦截或删除。
- 模型不可用、服务重启、继续生成、重新生成、采用版本、归档、恢复和永久删除均有测试覆盖。
- 原有测试、前端生产构建和桌面/窄屏端到端检查全部通过后，才视为本轮调试完成。

真实视觉模型的联网冒烟测试需要有效的模型认证；在认证接入前，自动化测试使用模拟模型验证完整数据流，不会把模拟结果冒充真实模型结果。
