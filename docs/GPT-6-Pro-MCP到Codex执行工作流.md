# GPT‑6 Pro + 只读 MCP → Codex 执行工作流

## 目标

这套流程把“看真实数据、判断问题”和“修改代码、运行测试”分开：

```text
工作台真实数据
→ 本机只读 MCP
→ GPT‑6 Pro 深度分析与规划
→ 添加到 Codex
→ GPT‑6 Astra / High 执行、测试和交付
```

MCP 只负责读取，不允许修改生产数据。Codex 负责代码和文件落地，并在独立工作树中验证。模型名称和推理档位取决于使用者账号当时可用的模型列表；界面没有对应选项时，应选择当时最强的规划模型和支持 High 的执行模型，不伪造可用性。

## 第一步：让 GPT‑6 Pro 读取真实数据

1. 按《相亲工作台只读 MCP 接入说明》配置 `scripts/mcp/matchmaking_readonly_mcp.py`。
2. 先调用 `list_workspaces`，使用返回的当前工作区 ID。
3. 根据任务调用品牌、任务、资料库、雷达和发布数据工具。
4. 分析小红书正文时优先调用：

```text
list_verified_xhs_archives(workspace_id, include_body=true)
```

该工具返回原始正文、验证状态、图片轮播序号、尺寸、字节大小和哈希。`PARTIAL` 只能作为部分证据，不能描述成完整帖子。

Web Clipper 可用于把普通网页和选中文本补充成 Markdown 资料；它不代替小红书归档的帖子 ID、原始图片字节和完整性校验。

## 第二步：要求 Pro 输出可执行计划

给规划模型的任务应要求输出：

- 已核实事实、推断和未知项；
- 要解决的具体问题和验收标准；
- 计划修改的文件；
- 数据迁移、回滚和安全边界；
- 测试命令与真实数据验收步骤；
- 明确禁止写生产数据库、导出登录态或绕过平台验证。

## 第三步：添加到 Codex

在支持该功能的 ChatGPT/Codex 界面点击“添加到 Codex”，把 Pro 的完整计划连同仓库上下文交给 Codex。执行设置选择 GPT‑6 Astra 与 High；如果界面当前没有该模型或档位，使用界面实际提供的最接近选项。

Codex 的执行提示词建议使用：

```text
在独立工作树中执行这份方案。先读取 AGENTS.md、当前代码、数据库 schema 和未提交改动；保护正式服务和生产数据。按计划实现后运行后端测试、前端构建和最小真实验收。不要导出 Cookie、Token 或带签名地址，不绕过登录、验证码、风控、地区或付费限制。完成后给出修改文件、测试退出码、日志、回滚步骤和仍受阻事项。未经明确要求，不替换正式安装、不推送远程仓库。
```

## 第四步：验收

计划交付不等于执行完成。至少核对：

- Git diff 与计划一致；
- 迁移在数据库副本上可重复执行；
- 自动测试和前端构建通过；
- 工作区隔离、失败恢复和敏感信息脱敏有效；
- 真实平台验证与模拟测试分开报告；
- 正式安装只在明确授权后更新。
