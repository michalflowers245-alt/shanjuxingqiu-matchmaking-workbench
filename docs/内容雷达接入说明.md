# 内容雷达接入说明

内容雷达现在有两条独立工作线：

1. **每日 IP 热点**：根据“我的 IP 信息”中已经填写的人设、受众、业务和内容方向，在小红书和抖音搜索页读取当前可见内容，并一次整理最多 12 个贴近账号的方向。
2. **主题搜索后创作**：临时想到一个主题时，直接搜索平台里实际显示的标题、文案摘要、作者、原文链接和可见互动信息，再从这些内容中延伸最多 12 个切入角度。

## 第一次使用：登录平台采集浏览器

1. 打开“内容雷达”，点击页面顶部的“打开双平台浏览器”。
2. 工作台会打开一个独立的 Chrome 窗口，并分别进入小红书和抖音搜索页。
3. 在平台自己的页面完成扫码登录。若抖音显示安全验证，也直接在该窗口完成。
4. 回到工作台点击“现在帮我找热点”或“先搜主题”。此后 Cookie、本地存储和登录会话会持续保留在这台电脑的 `.workbench/social_browser` 专用 Chrome 资料目录中；关闭工作台或重新开机后仍会复用，工作台不会主动清理。

“扫码登录”和“安全验证”不是一回事。扫码登录代表当前专用浏览器没有有效账号会话；安全验证属于平台风控，已经登录时也可能出现。平台可以主动让 Cookie 过期、撤销会话或再次要求验证，因此本机持久化能减少重复登录，但无法保证永远不再验证。

工作台只读取浏览器当前可见的公开页面，不接收账号密码、不导出 Cookie、不调用未公开签名接口，也不自动处理验证码。关闭专用浏览器后，定时任务会使用公开网页索引兜底；需要再次读取完整平台页面时重新点击打开即可。

## 两种日常用法

### 每日 IP 热点：不知道今天写什么时用

1. 先到“设置 → 我的 IP 信息”补充人设、服务对象、地域、表达边界和希望观众采取的动作。已有资料会继续使用，不需要重复填写。
2. 打开“内容雷达”，在“每日 IP 热点”卡片点击“开启每日监听”。
3. 工作台会保存一个仅属于当前工作区的每日雷达，立刻整理一次双平台方向，以后每天自动更新。
4. 工作台会分别显示小红书和抖音本轮筛出的数量，再从标题和文案表达中生成最多 12 个方向。有真实依据的卡片会直接显示“小红书原帖”或“抖音原帖”和可见点赞数；点击即可查看。点击“带入创作”后，真实原文链接、平台搜索入口和搜索词会一起进入文案任务。

系统会先要求结果命中至少两个具体检索词，避免“相亲相爱”这类字面碰巧命中的无关内容；再按搜索结果卡片当时真实可见的互动数排序。当前两个平台搜索卡片稳定可读的是点赞数；只有页面确实展示播放量、评论、收藏或转发时才会记录这些指标。

对于相亲账号，系统会优先分成三条可写的人设线：

- **柚子皮 · 同城线下相亲**：线下交友活动、扩大异性圈和本地真实场景；
- **小豆子 · 女性脱单红娘**：圈子小、主动认识异性、女性第一人称经验；
- **红娘案例 · 双账号共用**：相亲上岸、匹配过程和真实沟通细节。

每天的检查由本机工作台运行时的本地调度器执行。电脑休眠、关机或工作台没有运行时不会偷偷联网；下次打开工作台后，到期的每日雷达会补跑一次。

### 主题搜索后创作：已经有想法时用

1. 在“主题搜索后创作”输入主题，例如“第一次参加相亲活动要注意什么”。
2. 点击“先搜主题”，工作台会访问两个平台的搜索页，并列出实际找到的内容与原文链接。
3. 从最多 12 个可讲方向中选择一个。选择小红书文案或抖音口播后，工作台会把主题、真实原文和平台搜索入口带入三员工文案流程。
4. 在“作品记录”查看研究、初稿和主编审核结果；生成完成后再自行确认是否发布。

搜索结果里的短文字会明确标成“搜索页摘要”。每轮搜索后，工作台会自动读取前 6 篇小红书原帖的页面可见内容；这一步不再被称作“完整文案”。需要保存可校验素材时，在原帖卡片点击“保存原图与正文”。系统会严格核对帖子 ID、保存原始正文和按轮播顺序取得的图片响应字节，并生成清单、SHA-256 和诊断文件。只有身份、正文来源、全部预期图片和文件校验同时通过，状态才是“完整归档”。

小红书搜索卡片携带的短时访问参数会在工作台内存中保留 30 分钟，自动提取会优先复用；数据库和导出包中仍只保存干净的原帖链接。对于直接链接失效的帖子，工作台可以按标题搜索新的访问入口，但只接受与目标帖子 ID 完全一致的结果。标题相似但 ID 不同会返回 `IDENTITY_MISMATCH`，不会覆盖原记录。遇到登录或安全验证时，归档队列会暂停；完成验证后在原卡片点击“继续补齐”。

这个流程不会因为一次搜索就自动发布，也不会把未核实的搜索摘要写成事实。

## 小红书：本机可见页面采集

小红书没有面向普通开发者的全站自然笔记关键词搜索 API。工作台因此使用独立的本机 Chrome 打开官方搜索页，并读取登录后页面当前可见的笔记卡片。账号认证仍完全发生在小红书页面中；本地数据库会保存标题、摘要、作者、原文链接、可见互动信息和采集时间。

自动页面读取启动后，工作台会在同一个专用浏览器里打开原帖详情页，并按页面真实可见情况读取正文、OCR 和字幕辅助信息。严格图文归档是另一条独立链路，负责：

- 校验目标帖子 ID 与详情页实际帖子 ID；
- 将确认来源的 `body_raw` 原样保存，另建 `body_normalized` 用于搜索；
- 从同帖页面状态、有序轮播 DOM 和浏览器实际响应中建立图片槽位；
- 保存浏览器实际返回的图片字节，不截图代替、不重新编码；
- 保存 MIME、尺寸、字节数、SHA-256、来源、顺序、预期数量和缺失序号；
- 为每次尝试建立独立版本，PARTIAL 可以继续补齐，失败不会覆盖旧的 COMPLETE 版本；
- 按工作区校验图片下载权限，临时签名参数不写入数据库、日志或归档清单。

归档目录位于 `.workbench/xhs_archives/<workspace>/<post>/<archive>/`，包含 `metadata.json`、`manifest.json`、`checksums.sha256`、`diagnostics.json`、`body_raw.txt`、`body_normalized.txt` 和 `images/`。

本轮只完成图文归档最小闭环。视频帖没有完整媒体字节时会显示 `MEDIA_UNAVAILABLE`，不会把字幕或 OCR 冒充完整口播。登录失效、安全验证、访问频繁、帖子删除和页面结构变化会分别保存成可诊断状态；任务有队列、心跳、重启恢复和继续补齐入口，不会用虚假的完整度百分比掩盖缺失。
