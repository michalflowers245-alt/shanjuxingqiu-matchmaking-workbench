# AI 文案工作台

一个本地使用的极简自媒体文案产品。包含四个主题工作台，每个工作台都通过同一套三员工流程完成：

```text
研究员搜索并整理资料 → 文案员工生成初稿 → 主编审稿并去除机械表达 → 最终文案
```

## 使用

```powershell
python -m pip install -r requirements.txt
cd frontend
npm install
npm run build
cd ..
python -m backend.app.main
```

macOS 双击 `启动 AI 文案工作台.command`，Windows 双击 `启动文案工作台.bat`。macOS 首次运行会自动寻找 Python 3.10 或更高版本、建立独立的 `.venv` 并安装依赖；交付包已包含编译完成的前端，不要求接收方安装 Node.js。之后启动器会自动打开 `http://127.0.0.1:5177`。工作台已经运行且代码未变化时不会重复启动；检测到受本项目管理的旧版进程时会先安全退出旧版再启动新版。若旧进程缺少 PID 或版本标识，启动器会要求手动关闭，不会猜测并误杀其他进程。

首次使用时进入“设置”，任选一种模型连接：

- **本机 OpenAI OAuth 代理**：填写本机 OpenAI-compatible 代理根地址与模型名称，再点击“测试并保存”。代理应先在本机完成自己的 OpenAI OAuth 登录；工作台只向 `http://127.0.0.1`、`localhost` 或 `::1` 的 `/v1/chat/completions` 发起请求，OAuth Token 始终留在代理里。
- **DeepSeek API**：选择 `deepseek-v4-flash`（更快）、`deepseek-v4-pro`（更强）或图片案例用的 Vision 模型，填入 DeepSeek API Key 并点击“测试并启用 DeepSeek”。工作台固定连接官方 `https://api.deepseek.com`，只有测试成功后才把 Key 存入当前 Mac 的系统钥匙串；Key 不会写入文案、日志、SQLite 数据库或导出包。本机 OAuth 代理会保留，可随时重新测试并切回。

连接测试成功后，研究员、文案员工和主编才会使用当前模型；代理未运行、尚未完成 OAuth 登录、DeepSeek Key 无效或模型名称不正确时，设置页会给出明确原因。热点研究并行使用搜狗网页、Bing 新闻 RSS、Bing 网页 RSS 和资料库来源，不依赖模型侧联网工具；公开搜索源暂时失败时会自动使用资料库和用户主题继续，不会卡死整条任务。

## 四个内容工作台

- 朋友圈自动运营：输入本轮主题，生成连续 3、7 或 14 天的发布时间、内容角色、完整正文和互动承接。
- 生活案例朋友圈：上传 1–9 张生活图片并写下事情经过，生成“真实日常”“有感而发”“轻度业务启发”三篇可直接发布的朋友圈文案。
- 小红书 IP 文案：提供主题，自动读取“我的 IP 信息”，交付标题、正文、标签和可一键复制的发布版。
- 抖音情感文案：选择共鸣、治愈、遗憾、成长或关系清醒，生成约 30、60 或 90 秒的情感口播。

四种模式都不会补造经历、案例和效果；主编会确定性检查朋友圈周期、生活素材事实边界、小红书发布包和抖音前 3 秒情绪现场。

创作输入框下方的“没灵感？试试”会按当前内容模式显示 3 条灵感。点击“换一批”可从该模式的 15 条候选中继续轮换；朋友圈、小红书和抖音分别维护自己的灵感池。

生活案例朋友圈的完整操作、图片隐私和失败恢复说明见 [生活案例朋友圈工作台说明](docs/生活案例朋友圈工作台说明.md)。

## 内容雷达：每天找方向，主题搜完就创作

内容雷达提供两种入口：

- **每日 IP 热点**：从当前工作区已填写的人设、受众和内容方向出发，用本机可见浏览器读取双平台搜索结果，并一次生成最多 12 个可写方向。
- **主题搜索后创作**：输入任意主题，读取小红书笔记与抖音视频当前可见的标题、文案摘要、作者、原文链接和可见互动数，再生成最多 12 个推荐切入。

第一次使用时点击“打开双平台浏览器”，在专用 Chrome 中分别扫码登录。登录态由浏览器自己的独立用户目录保留；工作台不接收账号密码、不导出 Cookie，也不绕过验证码。搜索时只读取页面当前展示的公开内容卡片。遇到登录墙或安全验证会明确提示；页面暂不可读时，才使用公开网页索引和平台搜索入口兜底。创作任务会同时保留真实原文链接与搜索入口。完整步骤见 [内容雷达接入说明](docs/内容雷达接入说明.md)。

小红书结果卡现在会区分“搜索页摘要”“旧页面证据”和“严格归档”。点击“保存原图与正文”，工作台会在已登录的专用 Chrome 中核对帖子 ID，分别保存未改写的原始正文与规范化正文，并按轮播顺序保存浏览器实际返回的图片字节。只有身份、正文、预期图片数量、全部图片和校验清单均通过时才显示 `COMPLETE`；部分结果可以继续补齐，后续失败不会覆盖旧的完整归档。图片 OCR、页面字幕和 ASR 只作为辅助证据，不会冒充原始正文。

每日热点会分别显示小红书与抖音本轮筛出的数量。系统先排除和主题不够相关的结果，再按搜索页真实显示的点赞、评论、收藏、转发或播放等互动数据排序；平台页面没有展示的指标不会补造。由真实内容延伸的卡片会直接显示“小红书原帖”或“抖音原帖”与可见点赞数，点击即可核对原内容。

## 本机只读 MCP：给外部模型读取工作台数据

工作台附带 `scripts/mcp/matchmaking_readonly_mcp.py`。支持 MCP 的客户端可以通过标准输入输出读取当前工作区、品牌资料、文案任务、内容雷达、资料库、发布数据、生活案例摘要，以及已验证的小红书正文与图片证据。服务使用 SQLite 只读连接和固定查询工具，不提供任意 SQL、写入、删除、发布或登录能力；密钥字段会脱敏，访问元数据写入 `.workbench/mcp_audit.log`。配置示例和安全边界见 [相亲工作台只读 MCP 接入说明](docs/相亲工作台只读MCP接入说明.md)。

推荐的协作方式是：GPT‑6 Pro 通过只读 MCP 读取真实数据并完成深度分析与执行规划；在支持“添加到 Codex”的界面中把计划交给 Codex；执行任务选择 GPT‑6 Astra、推理强度 High，在独立工作树中实现、测试并提交。完整操作见 [GPT‑6 Pro、MCP 与 Codex 执行工作流](docs/GPT-6-Pro-MCP到Codex执行工作流.md)。

## 当前界面

- 开始创作：选择朋友圈运营、生活案例朋友圈、小红书或抖音工作台，并查看三名数字员工的真实进度。
- 内容雷达：本机可见浏览器读取小红书与抖音搜索结果，每日按 IP 生成最多 12 个方向，临时主题搜完即可创作。
- 作品记录：查看定稿、处理中和需要处理的任务；生活案例还支持素材预览、继续生成、归档和恢复。
- 设置：连接本机 OpenAI OAuth 代理或 DeepSeek API、查看公开搜索源/资料库状态、三个 Skill 的实际加载版本并维护“我的 IP 信息”。

旧作品和其他已有文案类型继续保存在作品记录中，但首页只突出这四个核心产品，避免再次变成功能堆砌。

默认代理地址为 `http://127.0.0.1:8787/v1`，默认模型为 `gpt-5.6-luna`。本机默认极速模式由本机完成联网研究和确定性主编校验，只调用一次 Luna 生成正文，推理强度为 `low`，同时关闭自动整轮返工。DeepSeek 的 Flash 会关闭深度思考以优先响应速度，Pro 保留深度思考。需要开发者调试原来的三次模型流程时，可在任务约束中设置 `quality_mode=deep`。启动器会同时拉起只监听本机的 Codex OAuth 兼容代理；它通过已登录的 Codex 会话完成模型调用，工作台本身不读取会话 Token。长文案会保留最长 12 分钟的本机等待时间，避免网络波动导致误判。联网研究并行查询三个公开入口；其中任意来源成功即可继续，全部失败时也会用资料库和用户主题完成创作。
